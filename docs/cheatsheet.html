Claude Code Cheat Sheet

The extension panel in Positron or VS Code first, plus the terminal CLI

For Part 2. Last checked against the docs (code.claude.com/docs): October 2026, Claude Code v2.1.28x. Claude Code changes often, so type / in the panel to see what your version has.

Where column: Both = the extension panel and the terminal CLI. Panel: … = how to do it in the panel when the typed command is CLI-only. CLI = terminal only (run claude in Positron’s Terminal; this needs the standalone CLI, because the extension doesn’t put claude on your PATH). † = varies by version or platform; check in Positron before relying on it. (if enabled) = depends on your organization’s admin settings.

Open Claude Code

Extension panel (main way in class) Terminal CLI
Start Spark icon in the editor toolbar, or ✻ Claude Code in the status bar claude in the Terminal tab
Install Extensions view → “Claude Code” by Anthropic (Positron: Open VSX †) Standalone CLI install
Commands A subset: type / to see yours All
Edits Side-by-side diff; accept or reject each change In the terminal, or a Positron diff via /ide

Keys and prefixes

Key What it does Where
/ Command menu: built-in commands, skills, Customize (Permissions, Hooks, Memory, Instructions) Both (menu: panel)
@file or @folder/ Point Claude at a file or folder (fuzzy match) Both
Option+K / Alt+K Insert an @-mention of the selected lines, e.g. @R/01_clean.R#5-10 Panel
Mode indicator / Shift+Tab Switch permission modes: Manual, Edit automatically, Plan, Auto (if enabled) Panel / CLI
Hover a message → rewind Fork the conversation, rewind code, or both Panel (CLI: Esc Esc)
Esc or Stop Stop Claude’s current turn; work so far is kept. Background agents keep running Both (panel: v2.1.286 or later)
Shift+Enter New line in the prompt Both
! at start Run a shell command yourself; output goes into context CLI
Tab Tab completion CLI

Commands you’ll use most

Command What it does Where
/status Version, account, model Both
/plan [task] Plan mode: read and propose, no edits Both (panel: also the mode indicator)
/compact [focus] Summarize the conversation to free space Both
/clear Start fresh; CLAUDE.md still loads CLI. Panel: new conversation/tab
/context See what’s filling the context window CLI. Panel: context indicator
/rewind Roll back code and/or conversation CLI. Panel: hover → rewind
/btw <question> Side question that isn’t added to the conversation Both
/memory Edit CLAUDE.md; review auto memory CLI. Panel: / → Customize → Instructions / Memory
/permissions View and edit allow/ask/deny rules CLI. Panel: / → Customize → Permissions
/hooks View configured hooks CLI. Panel: / → Customize → Hooks
/sandbox OS-level limits on shell commands (macOS, Linux, WSL2) Both
/skills, /reload-skills List skills / pick up skills added mid-session (needed if .claude/skills/ didn’t exist when the session started) Both / †
/agents Only prints a reminder now. To make a subagent, ask Claude to create one, or add a file to .claude/agents/ †
/tasks, /mcp Background work and subagents / connected servers (if enabled) Both
/usage Plan usage and limits Both
/export [file] Save the conversation as text Both
/init Draft a CLAUDE.md for a project † (CLI if not in your panel)
/doctor Setup checkup: diagnoses install, settings, extension, and CLAUDE.md problems and proposes fixes (alias /checkup; a bundled skill) †
/config Settings: theme, model, output style, and more. /config key=value sets one directly CLI. The panel doesn’t open it: type / and pick General config…, or edit a settings file
/diff, /code-review Review uncommitted changes / review the diff for bugs †
/resume Pick up an earlier conversation CLI. Panel: Session history button
/remote-control, /rc View and steer this local session from the Claude app’s Code tab or a browser (if enabled; off in the HIPAA configuration). Not the same as Claude Code on the web, which runs cloud sessions on a GitHub repo. CLI /mobile shows a QR code for the app Both (panel: no name, no QR code)

Models, effort, and workflows

Control What it does Where
/model <alias> default, opus, sonnet, haiku, fable / best (if available). Saved as your default CLI. Panel: click the model name at the bottom of the prompt box
opusplan Opus in plan mode, then Sonnet for execution Both (pick it as the model)
/effort <level> low, medium, high, xhigh, max. Opus 5.5, Sonnet 5.5, and Haiku 5.5 default to medium. max is session-only, and your org may cap levels CLI. Panel: Effort row in the model picker
ultrathink Type it in a prompt for deeper reasoning on that turn only Both †
ultracode Type it in a prompt to run that task as a dynamic workflow (if enabled). Doesn’t trigger in claude -p Both
/effort ultracode Workflows for every substantive task this session; /effort ultracode off to stop (if enabled) CLI. Panel: Ultracode switch under Effort †
/deep-research <question> Bundled workflow: web search, cross-checked sources, cited report (if enabled) Both †
/workflows Watch, pause, or stop workflow runs CLI †
/fast Faster Opus at a higher price per token; usage credits on subscription plans (if enabled) CLI. Panel: Toggle fast mode

Workflows and ultracode can use meaningfully more tokens and count toward your usage limits. Try a small slice first. Remote Control stores the session transcript on Anthropic servers while connected, so don’t print data values into the session.

Key files

File What it’s for Shared?
CLAUDE.md Project rules Claude reads every session. Keep it under ~200 lines. Team (commit it)
CLAUDE.local.md / ~/.claude/CLAUDE.md Your notes for this project / for every project Just you
.claude/settings.json Permissions, sandbox, hooks Team (commit it)
.claude/settings.local.json Your approvals and overrides Just you (gitignored)
.claude/skills/<name>/SKILL.md Skill → /<name>, or loaded when the description matches. Add disable-model-invocation: true to run it only when you type it Team (~/.claude/skills/: just you)
.claude/commands/<name>.md Older form of a skill (custom commands were merged into skills). Still works; use skills/ for new ones Team
.claude/agents/<name>.md Subagent with its own instructions and tools Team (~/.claude/agents/: just you)
.mcp.json Project MCP servers, only if approved (if enabled) Team

A deny rule at any level wins, and managed settings from your organization override everything. The panel’s starting permission mode comes from your user settings (claudeCode.initialPermissionMode), not the project’s .claude/settings.json.

CLI only

Command What it does
claude -c / claude --resume Continue the last conversation / pick one, including panel conversations
claude --model <alias> / --effort <level> Choose the model or effort for this session (--effort ultracode also sets xhigh)
claude -p "task" --allowedTools "Read" Run once without the interactive interface, pre-approving only listed tools
claude --worktree <name> Start in a separate git checkout
claude --remote-control "name" / claude remote-control Start with Remote Control on / server mode with a QR code (if enabled)
claude update / claude -v Update / print the version (record it in your lab notebook)

Which feature should I use?

When this happens… Add… Example
Claude gets a convention wrong twice A line in CLAUDE.md “Use here::here() for paths”
You keep typing the same starting prompt A skill you run by name (disable-model-invocation: true) /check-data
You paste the same multi-step procedure again A skill Claude loads when relevant table1
You want an independent second opinion A subagent (ask Claude to create one) biostat-reviewer
Something must happen every time A hook Block edits to data/raw/
Claude must never do something A deny rule (+ the sandbox) Deny reads of data/restricted/
A hard problem needs more thought ultrathink, or a higher /effort Missing-data assumptions
A big task needs many independent checks ultracode (if enabled) Review every script against the SAP

Remember: CLAUDE.md and skills are advice. Permissions, the sandbox, and hooks are enforced. Claude Code sends what it reads, so never put real patient data in a project folder because a guardrail is on. A HIPAA-supported version of Claude is available by request ([request link]), but that doesn’t approve your project, and the Positron/VS Code extension may not be covered [confirm with ITS which Claude Code surfaces are covered].
